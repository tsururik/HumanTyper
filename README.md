# HumanTyper

Нативное macOS-приложение (Swift/SwiftUI), которое набирает текст посимвольно в любом
текстовом поле любой программы и имитирует живого человека: неровный темп, паузы после
знаков препинания и абзацев, опечатки с исправлениями и короткие перерывы.

- Живёт в строке меню и открывает отдельное окно с текстом и настройками.
- Печатает через `CGEvent` со строкой Unicode, поэтому кириллица, латиница, эмодзи и любые
  символы набираются независимо от текущей раскладки. `\n` — клавиша Return, `\t` — Tab.
- Работает на macOS 13 Ventura и новее.

### Установка

1. Откройте скачанный `HumanTyper.dmg` и перетащите **HumanTyper** на ярлык **«Программы»**.
2. Запустите HumanTyper из «Программ» или через Spotlight.
3. Приложение не нотаризовано Apple, поэтому при первом запуске macOS его заблокирует.
   - В окне с предупреждением нажмите **«Готово»**.
   - Откройте **Системные настройки → Конфиденциальность и безопасность**, прокрутите вниз
     до сообщения о HumanTyper, нажмите **«Всё равно открыть»** и подтвердите паролем или
     Touch ID.

   Вместо этого можно снять блокировку командой в Терминале:

   ```bash
   xattr -dr com.apple.quarantine /Applications/HumanTyper.app
   ```

4. Выдайте доступ к «Универсальному доступу» — см. раздел [Разрешения](#разрешения).
5. В строке меню появится значок клавиатуры. В Dock приложения нет, так и задумано.

**Обновление.** Скачайте новый DMG, закройте HumanTyper (значок в строке меню → «Выйти»)
и замените приложение в «Программах». У новой версии другая подпись, поэтому доступ к
Универсальному доступу нужно выдать заново (см. [Разрешения](#разрешения)).

## Сборка

Нужен Xcode 16 или новее (проект использует синхронизируемые папки Xcode 16; собран и
проверен в Xcode 27).

```bash
cd HumanTyper

# Release-сборка
xcodebuild -project HumanTyper.xcodeproj -scheme HumanTyper -configuration Release \
  -derivedDataPath build build

# Unit-тесты движка
xcodebuild -project HumanTyper.xcodeproj -scheme HumanTyper -derivedDataPath build test
```

Готовое приложение: `build/Build/Products/Release/HumanTyper.app`. Скопируйте его в
`/Applications` и запустите:

```bash
cp -R build/Build/Products/Release/HumanTyper.app /Applications/
open /Applications/HumanTyper.app
```

Можно и просто открыть `HumanTyper.xcodeproj` в Xcode и нажать ⌘R.

### Выпуск новой версии

1. Поднимите `MARKETING_VERSION` у таргета HumanTyper.
2. Соберите DMG и опубликуйте релиз:

   ```bash
   scripts/package.sh
   gh release create v1.1 dist/HumanTyper.dmg --title "HumanTyper 1.1" --notes "Что изменилось…"
   ```

   `scripts/package.sh` собирает Universal-версию (Apple Silicon + Intel), проверяет подпись
   и упаковывает приложение в `dist/HumanTyper.dmg` с ярлыком «Программы».

Не меняйте имя файла `HumanTyper.dmg`: на него ведёт постоянная ссылка
`releases/latest/download/HumanTyper.dmg` из раздела «Скачать».

## Разрешения

Слать нажатия клавиш в другие приложения и видеть глобальный Esc macOS позволяет только
программам из списка **«Универсальный доступ»**.

1. При первом запуске HumanTyper покажет экран «Нужен доступ…».
2. Нажмите **«Открыть Системные настройки»**: откроется
   *Системные настройки → Конфиденциальность и безопасность → Универсальный доступ*.
3. Включите переключатель у **HumanTyper**. Если приложения нет в списке, нажмите «+» и
   выберите `HumanTyper.app`.
4. Вернитесь в HumanTyper: окно обновится само в течение секунды, перезапуск не нужен.

> **После пересборки разрешение «слетает».** По умолчанию проект подписывается локально
> (ad-hoc), и у каждой новой сборки другая подпись. Переключатель в настройках при этом
> остаётся включённым, но не действует. Сбросьте запись и выдайте доступ заново:
>
> ```bash
> tccutil reset Accessibility com.humantyper.HumanTyper
> ```
>
> Чтобы так не делать после каждой сборки, укажите свою команду разработчика
> (Signing & Capabilities → Team, или `DEVELOPMENT_TEAM=XXXXXXXXXX` в `xcodebuild`).
> Тогда подпись стабильна и доступ сохраняется между пересборками.

Песочница (App Sandbox) отключена намеренно: из песочницы нельзя отправлять события
клавиатуры в чужие приложения.

## Как пользоваться

1. Вставьте текст в окно HumanTyper (кнопка **«Вставить из буфера»** или ⌘V).
2. Нажмите **«Старт»** (⌘↩). HumanTyper скроется, фокус вернётся в приложение, где вы
   работали до этого, и начнётся обратный отсчёт **3 секунды**. За это время поставьте
   курсор в нужное поле.
3. Или сразу поставьте курсор в нужное поле и нажмите **⌃⌥T**: набор начнётся без отсчёта,
   как только вы отпустите модификаторы.

| Действие | Клавиши |
|---|---|
| Старт | ⌃⌥T (настраивается) |
| Пауза / продолжить | ⌃⌥P (настраивается) |
| Экстренная остановка | Esc |

**Автопауза.** Если во время набора активным станет другое приложение (переключились,
кликнули по уведомлению, открыли меню HumanTyper), набор встанет на паузу, чтобы текст не
ушёл в чужое окно. Чтобы продолжить, вернитесь в исходное приложение и нажмите ⌃⌥P.
Продолжить в другом приложении нельзя.

Прогресс (набрано / всего, оставшееся время, перерывы) виден в окне и в меню строки меню.
Значок в строке меню показывает отсчёт и процент набора.

## Настройки

Хранятся в `UserDefaults` (`@AppStorage`).

| Параметр | Диапазон | По умолчанию | Что делает |
|---|---|---|---|
| Скорость | 30–150 WPM | 60 | Задержка = 60 / (WPM × 5) с, разброс ±40% по нормальному распределению (±40% = 2σ, хвосты обрезаются) |
| Опечатки | 0–20% | 3% | Соседняя клавиша QWERTY/ЙЦУКЕН → пауза 150–600 мс → Backspace → правильный символ. ~20% ошибок замечаются через 1–3 символа, и стирается всё набранное после ошибки |
| Естественный ритм | вкл/выкл | вкл | +50–150 мс после пробела, +0,2–0,5 с после запятой, +0,4–1,2 с после . ! ?, +1–3 с после абзаца; заглавные ×1,35, спецсимволы ×1,5 |
| Перерывы | каждые X–Y с, на A–B с | 30–120 с, 3–15 с | Перерыв только между словами и никогда посреди исправления |
| Тема | системная / светлая / тёмная | системная | |

Изменения скорости, опечаток, ритма и перерывов применяются со следующего старта: план
набора рассчитывается целиком в момент запуска.

## Архитектура

```
HumanTyper.xcodeproj
├── TypingEngine/          фреймворк (статический), чистая логика без AppKit
│   ├── TypingSettings     параметры и константы ритма
│   ├── DelayModel         задержки от WPM, нормальный разброс, паузы ритма
│   ├── KeyboardLayout     QWERTY / ЙЦУКЕН → карта соседних клавиш (по геометрии рядов)
│   ├── TypingEngine       строит план: опечатки, отложенные исправления, перерывы
│   ├── TypingPlan         шаги «подождать → символ / Backspace / перерыв»
│   └── Random             нормальное распределение, seeded-генератор для тестов
├── HumanTyper/            приложение
│   ├── App/               @main (MenuBarExtra + Window), TypingController (состояние),
│   │                      TypingRunner (фоновое выполнение плана)
│   ├── KeyboardOutput/    протокол KeyboardOutput + CGEventKeyboardOutput
│   ├── HotkeyManager/     Hotkey, HotkeyManager (Carbon RegisterEventHotKey),
│   │                      EscapeMonitor (NSEvent global/local monitor)
│   ├── Permissions/       AccessibilityPermission (AXIsProcessTrustedWithOptions)
│   ├── Settings/          ключи и значения по умолчанию, тема
│   └── UI/                окно, панель текста, настройки, экран разрешений, меню
├── TypingEngineTests/     XCTest для движка
├── Design/                логотип и генератор иконки (swift Design/make_icon.swift)
└── scripts/package.sh     сборка Universal-версии и упаковка в DMG
```

- **План набора рассчитывается заранее.** `TypingEngine` не нажимает клавиши, а выдаёт
  последовательность шагов. Это даёт точное оставшееся время и детерминированные тесты:
  применив все шаги к пустому буферу, получаем исходный текст.
- **`TypingRunner`** выполняет план в `Task.detached`. Паузу и отмену он проверяет каждые
  50 мс, перед каждым нажатием ждёт, пока пользователь отпустит ⌘⌃⌥⇧, и сообщает прогресс
  в интерфейс через `AsyncStream`.
- **⌃⌥T / ⌃⌥P** регистрируются через Carbon `RegisterEventHotKey`: сочетание перехватывается
  и не попадает в целевое окно. **Esc** ловится глобальным монитором `NSEvent`, он включён
  только во время набора. У источника событий отключено подавление реальной клавиатуры
  (`localEventsSuppressionInterval = 0`), иначе Esc мог бы не дойти.

## Тесты

`TypingEngineTests` — 31 тест:

- задержки: база от WPM, разброс в пределах ±40% со средним около базы, замедление
  заглавных и спецсимволов, диапазоны пауз ритма, отсутствие пауз внутри «3.14» и «1,5»;
- раскладки: соседи для QWERTY и ЙЦУКЕН, симметрия, сохранение регистра, отсутствие
  опечаток для пробелов, пунктуации и эмодзи;
- движок: итоговый текст после всех опечаток и исправлений совпадает с исходным
  (сотни seed'ов, частота опечаток до 100%, кириллица, эмодзи, табуляция, переводы строк
  и `\r\n`); доля отложенных исправлений около 20%; исправление никогда не стирает перевод
  строки или табуляцию; перерывы в заданных границах и только между словами; прогресс
  монотонный; средняя скорость соответствует WPM; детерминированность по seed.

## Ограничения

- **Автозамена в целевом приложении** (смарт-кавычки, «--» → «—», автозаглавные буквы,
  автодополнение и автозакрытие скобок в редакторах кода) может изменить набранный текст.
  При необходимости отключите её в целевом приложении.
- **Return в мессенджерах отправляет сообщение, Tab в веб-формах переводит фокус.** Движок
  никогда не стирает уже набранные переводы строк и табуляции, но сами эти символы будут
  нажаты.
- Используйте обычную раскладку (ABC, «Русская»). Методы ввода с подбором слов (китайский,
  японский) могут перехватывать события.
- Некоторые программы читают код клавиши, а не символ (часть игр, удалённые рабочие столы,
  виртуальные машины). В них Unicode-события могут не работать.
- Автопауза срабатывает по уведомлению о смене активного приложения. Между переключением
  и паузой может проскочить один символ.
